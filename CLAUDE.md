# Romchi Website

Публичный сайт для покупателей мобильного приложения **Romchi** (Android и iOS).

## О приложении
Romchi — приложение для мастеров и компаний, которые производят и устанавливают окна и двери из алюминия и ПВХ в Узбекистане. Слоган: «Romchi — sizga yordamchi».
Функции: редактор окон/дверей/арок (размеры, створки, импосты, шаблоны), расчёт цены в сумах и долларах по профилям (Akfa, Imzo, Alutex и др.), себестоимость/прибыль/отходы, схема раскроя, 3D-просмотр и AR, заказы и PDF клиенту, склад, дилеры, Premium-подписка.

## Цель сайта
Объяснить, что такое Romchi, показать программу, дать попробовать демо на образцах («Sinab ko'ring»), привести к скачиванию приложения или заявке. Последний этап — 3D + AR через камеру.

**Актуальный план: [docs/plan-v2.md](docs/plan-v2.md)** — сайт-конструктор для обычных людей из Instagram-рекламы (сразу «Sinab koʻring»). Читать перед любой задачей. Старый план для мастеров: [docs/plan.md](docs/plan.md) (архив, ничего не удалять).

Профили — только реальные бренды с romchi.uz (17 шт., список в plan-v2). **Imzo не использовать.** Бренд-цвет #0077FF.
Логотип — только оригинал от команды: `web/public/logo.svg` (контуры в `web/lib/brand.ts`, компонент `LogoMark`). Не перерисовывать и не заменять текстом.

## Правила
- Язык интерфейса сайта: узбекский (латиница). Позже — русский (i18n uz/ru с самого начала).
- Mobile-first: много трафика с телефонов и из встроенного браузера Telegram.
- Современный уникальный дизайн, много анимаций, но быстро: Lighthouse 90+ на мобильном, `prefers-reduced-motion` уважаем.
- Не выдумывать цифры, отзывы и цены: демо-цены помечаются как примерные.

## Стек
- Next.js (App Router) + TypeScript + Tailwind CSS
- Анимации: GSAP + ScrollTrigger, Lenis, Framer Motion
- 3D: React Three Fiber + drei (декоративные окна строим в коде)
- AR (позже): `<model-viewer>` (GLB + USDZ)
- Бэкенд: Node.js + PostgreSQL, headless CMS (Strapi / Directus), заявки → Telegram-бот

## Скиллы
Каталог по категориям (дизайн, анимации, код, 3D, схемы): [docs/skills/README.md](docs/skills/README.md). Сами скиллы лежат плоско в `.claude/skills/<имя>/` — не переносить в подпапки, иначе Claude Code их не найдёт.

### Обязательные правила: какой скилл когда
Перед задачей из списка ниже ОБЯЗАТЕЛЬНО загрузить указанные скиллы, даже если пользователь их не назвал. Если пользователь явно назвал другой скилл — следовать ему.

| Задача | Скиллы (по порядку) |
|---|---|
| Выбор стиля, палитры, шрифтов; создание или правка DESIGN.md | `ui-ux-pro-max` → `/impeccable init` (или `/impeccable document`) |
| Новая страница или секция, редизайн | `design-taste-frontend` + `impeccable`, следовать DESIGN.md |
| Правка внешнего вида существующего UI | `impeccable` |
| Любая анимация, переход, hover/press, скролл-эффект | `emil-design-eng` (+ `/impeccable animate` для общего плана анимаций) |
| Toast-уведомления | `ask-sonner` |
| Перед коммитом любых изменений дизайна или UI | `/impeccable polish`, затем `/impeccable audit` |
| Разбор, «почему выглядит плохо», ревью дизайна | `/impeccable critique` |
| 3D-модель окна/двери, файлы GLB/USDZ для сайта и AR | `blender-pro-workflow` → `blender-modeling` → `blender-materials` → `blender-export` (код через `bpy` в облаке, см. docs/skills/4-3d) |
| Точная геометрия профиля, размеры, STEP/STL | `cad` |
| Иллюстрация «как устроено» (окно, створка, фурнитура) | `anatomy` |
| Схема архитектуры сайта/бэкенда, потоки данных | `archify` |

Общие правила для всех скиллов:
- Не выдумывать цифры, отзывы и цены (см. «Правила» выше).
- Анимации: уважать `prefers-reduced-motion`, держать Lighthouse 90+ на мобильном.
- Если скиллы противоречат друг другу — приоритет: DESIGN.md → `impeccable` → остальные.

### Скиллы дизайна (`.claude/skills/`)
| Скилл | Когда использовать |
|---|---|
| `design-taste-frontend` (Taste Skill) | Новая страница/секция: уникальный визуальный стиль без «шаблонного AI-вида» |
| `frontend-design` (Anthropic) | Базовые принципы дизайна интерфейса |
| `impeccable` | Дизайн, аудит, критика, анимация, финальная полировка: `/impeccable polish`, `/impeccable audit`, `/impeccable critique`, `/impeccable animate` |
| `emil-design-eng` (Emil Kowalski) | Анимации и микро-взаимодействия: easing, длительность, spring, детали |
| `ask-sonner` | Toast-уведомления через библиотеку Sonner (например, «заявка отправлена») |
| `ui-ux-pro-max` | Подбор стиля, палитры, шрифтов, UX-правила |

### Скиллы 3D и схем
| Скилл | Когда использовать | Что нужно на компьютере |
|---|---|---|
| `anatomy` | Интерактивные изометрические «машины»-иллюстрации (SVG/WebGL), например как устроено окно: рама, створка, фурнитура | Node.js 20+ |
| `text-to-blender` + `blender-*` | 3D-модели окон/дверей в Blender: моделирование, материалы, свет, рендер, экспорт GLB/USDZ для AR | Ноутбук не нужен: Blender работает в облаке без окна (`pip install bpy`), см. docs/skills/4-3d |
| `cad` (Text-to-CAD) | Точные параметрические модели профиля/изделия (build123d), экспорт STEP/STL/GLB | `pip install build123d` (в облаке уже установлен) |
| `archify` | Архитектурные схемы и диаграммы (сайт, бэкенд, потоки данных) в виде HTML | Node.js |

Дизайн-система сайта описывается в `DESIGN.md` (и контекст продукта в `PRODUCT.md`) в корне репозитория — создаются на этапе дизайна (`/impeccable init` или `/impeccable document`). Все скиллы должны следовать DESIGN.md.

## Структура репозитория (план)
